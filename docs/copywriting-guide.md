# 文案规范（AiVerse strings.xml 约定）

新增或修改 `app/src/main/res/values/strings.xml`（中文）与 `values-en/strings.xml`（英文）文案时遵循以下约定。

## 人称与语气

- 设置项标题、说明、按钮统一用**中性口径**，描述「是什么、做什么」，避免第一人称（我/我的/我来）与口语化问句。
  - 例：`bubble_user` 用「用户消息气泡」，不用「我发出的气泡」；`editor_save_conflict_discard` 用「放弃修改」，不用「放弃我的修改」。
- 功能说明可带「你」字指代用户操作，但避免「帮你」「我来」这类把 AI 当主语的口语表达。
- 弹窗确认统一为「动作 + 影响 + 是否继续？」结构，动词置于句首。

## 字数上限

- 设置项标题 / label：建议 **≤ 10 字**。
- 设置项副标题 / 说明（desc / subtitle / hint / note）：建议 **≤ 30 字**，最多不超过 **40 字**；超过时优先压缩冗余修饰，保留关键信息。
- 确认弹窗 / 警告正文：建议 **≤ 35 字**；风险说明（删除、凭据、网络）可放宽，但不低于可读性。
- 单行能放下：窄屏或大字号下说明折行会撑高设置行，优先让说明一句话说清。

## 双语与占位符

- **中英必须成对**：中文新增 key 必须同步在 `values-en/strings.xml` 新增对应英文；反之亦然。不得只加中文。
- **占位符一致**：`%1$s` / `%1$d` 的数量与类型中英必须相同，且 `%1$s` 等参数顺序对应；缺一会在格式化时报错。
- 英文用自然、地道的表达，避免机翻腔；保留 `&amp;`、`\"`、`\'` 等 XML 转义。
- 文案里**不用 emoji**。

## 命名

- key 用语义化英文小写下划线，跨页面复用加 `common_` 前缀。
- 描述类 key 建议带 `_desc` / `_hint` / `_note` / `_subtitle` 后缀，便于定位。
