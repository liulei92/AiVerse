# AiVerse 官网编写提示词（AI 协作规范）

> 用途：当用 AI 协助修改本官网时，把本文件作为系统提示词 / 上下文喂给 AI。
> 目标：让 AI 在**不破坏现有样式**的前提下安全修改站点，并知晓移动端适配的坑。

---

## 一、项目本质（必须先懂，否则会改坏）

本站是 **VitePress 构建产物的静态部署**，**服务器上没有完整源码、没有 node/npm、无法重新构建**。一切修改都是**直接改产物文件**。

### 1. 三层样式叠加（记住这个，别去改第①层）

| 层 | 文件 | 谁写的 | 能不能改 |
|---|---|---|---|
| ① 基础样式 | `index.html` 等页面里 `<style>` 内联块（首页约 13 万字符 / 1107 条规则） | **VitePress 官方主题**，构建时自动生成 | **❌ 绝不改**。它是全站底子，改了会全站崩、且下次更新覆盖就丢 |
| ② 样式覆盖 | `/custom.css`（页面用 `<link>` 引入）+ 部分页面 `<style>` 里的自定义块（带中文注释） | **本站自己** | ✅ **改这里**。所有样式调整都在 custom.css |
| ③ 功能增强 | `/site-enhance.js`（`?v=2` 引入，约 205 行 JS） | **本站自己** | ✅ **改这里**。语言切换、移动菜单注入、下载过渡等交互逻辑 |

### 2. 文件结构

```
/var/www/html/aiverse/
├── index.html          首页（中文，构建产物，含 13 万字符内联官方 CSS）
├── en/index.html       首页（英文）
├── guide/*.html        使用手册页（37 篇，静态产物）
├── advanced/*.html     进阶教程页（静态产物）
├── custom.css          ★ 样式覆盖层（改样式主要动这里）
├── site-enhance.js     ★ 功能增强层（改交互主要动这里）
├── md/                 内容源 Markdown（教程页的源，但当前无渲染器，仅供修改对照/备份）
│   ├── guide/   37 篇
│   ├── advanced/ 7 篇
│   └── en/       6 篇
├── gh_proxy.php        GitHub 加速反代
├── trigger/            触发构建页面
└── download.html       下载页
```

### 2.1 本地文档源结构（`docs-site/docs/`，内容唯一事实源）

仓库内的 `docs-site/docs/` 是文档**唯一事实源**（source of truth），与服务器 `md/` 内容一一对应。改文档优先改这里，再同步到服务器产物。

```
docs-site/docs/
├── guide/              中文使用手册（37 篇，功能说明）
│   ├── overview.md     功能总览索引（新增页面要同步加进这里）
│   ├── quick-start.md  快速上手
│   └── *.md
├── advanced/           中文进阶教程（7 篇，环境搭建与进阶）
│   ├── reasoning-modes.md
│   └── *.md
├── en/                 ★ 英文文档（与中文一一对应）
│   ├── guide/          英文使用手册（providers / overview / free-providers / quick-start）
│   ├── privacy.md      英文隐私政策
│   └── terms.md        英文用户协议
└── 官网编写提示词.md    本文件（AI 协作规范）
```

### 3. 两种内容修改路径

- **改样式 / 布局 / 响应式** → 改 `custom.css`（或页面内自定义 `<style>` 块）
- **改交互 / 功能 / 注入元素** → 改 `site-enhance.js`
- **改教程正文** → 理论上改 `md/` 源，但**当前没有 md→html 渲染器**，所以实际要同步改对应 `.html` 产物的正文部分（谨慎，产物里正文夹在大量标记中）
- **首页 hero 文案 / 免责声明等特殊内容** → 直接改 `index.html` 对应位置（首页无 md 源）
- **改文档正文（推荐）** → 改仓库 `docs-site/docs/{guide,advanced}/*.md` 源文件，这是唯一事实源；改完再同步到服务器 `md/` 与对应 `.html` 产物

### 3.1 中英文必须同时写（硬规则）

**任何面向用户的文档/文案改动，中文与英文必须同步更新，不允许只改一种语言。**

- 改了 `docs-site/docs/guide/*.md`（中文使用手册）→ 同步改 `docs-site/docs/en/guide/` 下对应英文页
- 改了 `advanced/`（中文进阶）→ 同步 `en/` 对应英文进阶页（如有）
- 改了中文隐私政策 / 用户协议 → 同步 `en/privacy.md` / `en/terms.md`
- 英文不是机翻堆砌：保持术语一致、语句地道，与中文语义对齐
- 新增文档页：中英文**成对新建**，并同步加进侧栏（`.vitepress/config.ts`）与 `guide/overview.md` 索引（英文 `en/guide/overview.md`）

> 一句话：**中文动一笔，英文跟一笔；只交一种语言 = 任务没完成。**

### 3.2 编写完成后上传到服务器（SSH）

本地 `docs-site/docs/` 改完后，要把变更同步到服务器 `/var/www/html/aiverse/`。

**服务器信息**

| 项 | 值 |
|---|---|
| 目标根目录 | `/var/www/html/aiverse/` |
| md 源目录 | `/var/www/html/aiverse/md/`（root 所有，写入需 `sudo`） |
| SSH 用户 | `ubuntu`（在 sudo 组，**免密 sudo 可用**） |
| html 产物目录 | `/var/www/html/aiverse/{guide,advanced,en}/` |

**路径对应关系**

| 本地（仓库） | 服务器 |
|---|---|
| `docs-site/docs/guide/*.md` | `/var/www/html/aiverse/md/guide/*.md` |
| `docs-site/docs/advanced/*.md` | `/var/www/html/aiverse/md/advanced/*.md` |
| `docs-site/docs/en/guide/*.md` | `/var/www/html/aiverse/md/en/guide/*.md` |
| `docs-site/docs/en/{privacy,terms}.md` | `/var/www/html/aiverse/md/en/` |

**上传命令**（本地仓库根执行；`md/` 需 sudo，先传 `/tmp` 再 `sudo mv` 绕开权限）：

```bash
# 单文件
scp docs-site/docs/guide/overview.md ubuntu@<host>:/tmp/
ssh ubuntu@<host> 'sudo cp /tmp/overview.md /var/www/html/aiverse/md/guide/'

# 整目录递归同步（推荐，rsync 保持结构）
rsync -av docs-site/docs/guide/    ubuntu@<host>:/tmp/_sync/guide/
rsync -av docs-site/docs/advanced/ ubuntu@<host>:/tmp/_sync/advanced/
rsync -av docs-site/docs/en/       ubuntu@<host>:/tmp/_sync/en/
ssh ubuntu@<host> 'sudo rsync -a /tmp/_sync/ /var/www/html/aiverse/md/ && sudo rm -rf /tmp/_sync'
```

> `<host>` = SSH 配置里的主机名 / IP / 别名。

**⚠️ 上传 md ≠ 线上更新**

服务器**无 md→html 渲染器、无 node/npm**，`/guide/*.html`、`/advanced/*.html` 是 VitePress **预构建静态产物**。只上传 `.md` 到 `md/` **只更新了源备份，线上 html 不会变**。要让线上正文真变，必须**同时更新对应 `.html` 产物的正文部分**（谨慎，正文夹在大量标记中，改前务必备份，见二.3）。

完整流程：① 改本地 md（中英文同步）→ ② 上传 md 到 `md/`（更新源）→ ③ 同步更新对应 `.html` 产物正文 + 绕 CDN 实测，线上才生效。

## 二、硬规则（违反 = 改坏站点）

1. **永不修改页面里那段庞大的内联 `<style>`（VitePress 官方主题 CSS）**。要覆盖样式，一律在 `custom.css` 里写更高优先级规则（必要时用 `!important` 或更具体选择器）。
2. **保留所有 `data-v-*` 属性**。它们是 Vue 作用域 CSS 哈希，删了样式失效。
3. **改产物前必须备份**：`cp -a xxx.html xxx.html.bak.$(date +%Y%m%d-%H%M%S)`。
4. **改完必须实测**：本站走 CDN，测试要绕过——用 `curl --resolve www.aivapp.cn:443:127.0.0.1 https://www.aivapp.cn/...`。
5. **改 `site-enhance.js` 要升版本号** `?v=2` → `?v=3`，避免浏览器缓存。
6. **中英文页面要同步**：改了 `index.html` 通常也要改 `en/index.html`（对应英文）。
7. **CSS 优先用官方变量**（`var(--vp-c-brand-1)`、`var(--vp-c-text-1)`、`var(--vp-c-warning-soft)` 等），保证深色模式 / 主题一致性，别写死颜色。

## 三、当前已知问题：移动端被官方 CSS 阉割

VitePress 官方主题用响应式媒体查询**故意隐藏**了移动端的多个导航元素（这是官方默认，不是站点改坏的）。已定位：

| 元素 | 官方规则 | 现状 |
|---|---|---|
| `.VPNavBarMenu`（顶部菜单：快速上手 / 进阶教程 / 下载 / 用户协议 / 隐私） | `display:none`；`@media(min-width:768px)` 才 `display:flex` | 手机端顶部菜单**整条消失** |
| `.VPNavBarSocialLinks`（**GitHub 图标**） | `display:none`；`@media(min-width:1280px)` 才显示 | 手机 / 平板**看不到 GitHub** |
| `.VPNavBarTranslations`（语言切换） | `display:none`；`@media(min-width:1280px)` 才显示 | 手机端**看不到语言切换** |

**修复方向**（在 `custom.css` 写覆盖，把断点下探或在移动端强制显示）：
- 让 GitHub 社交图标在手机端也显示：覆盖 `.VPNavBarSocialLinks`，在 `@media(max-width:1279px)` 下 `display:flex`（需权衡顶部空间，可只保留 GitHub 图标、缩小尺寸）。
- 让顶部菜单或其关键项在手机端可达（当前靠 `site-enhance.js` 注入的汉堡菜单补偿，可继续强化）。
- 语言切换在手机端入口（`site-enhance.js` 已注入移动菜单，可确认是否够用）。

**要求**：优化移动端时，**不得破坏电脑端现有外观**；电脑端（≥1280px）当前是完整的，改动应只在窄屏媒体查询内生效。

## 四、给 AI 的标准工作流

1. 先确认要改的是**样式**（→ custom.css）、**功能**（→ site-enhance.js）、还是**正文内容**（→ html 产物正文 / md 源）。
2. 备份目标文件。
3. 用官方 CSS 变量写覆盖规则，改动限定在必要的媒体查询内。
4. 改 `site-enhance.js` 记得升 `?v=N`。
5. 绕 CDN 实测（电脑 UA + 手机 UA 各看一次），确认电脑端没被影响、手机端达到预期。
6. 中英文页面同步。
7. 编写/修改完成后，把 `docs-site/docs/` 同步上传到服务器 `/var/www/html/aiverse/md/`（需 sudo，见 3.2），并按需更新对应 `.html` 产物。

## 五、一句话心智模型

> 官方 13 万行内联 CSS 是"底子"（别碰）→ 你的 `custom.css`（样式）和 `site-enhance.js`（功能）叠在上面（改这里）→ 移动端导航元素被官方媒体查询隐藏（要补就改 custom.css 的窄屏规则）→ 改前备份、改后绕 CDN 实测、中英文同步。
